Six Concepts · 六大概念

从解耦架构到量化压缩

六个概念沿着一条主线排列：先理解这套生态为什么能通用（概念 I–III），再理解数据不够时怎么办（概念 IV），最后理解跑得动之后怎么变小变快（概念 V–VI）。

Concept I

Tokenizer ↔ AutoModel 解耦

是什么：分词器（把文本切成 token 并映射为整数 ID）和模型权重是两个独立保存、独立加载的组件，二者靠一个共享的 checkpoint 名字（比如 bert-base-uncased）对齐词表版本。

原文定义：书中用 AutoTokenizer.from_pretrained() 和 AutoModel.from_pretrained() 这对函数具体化这个抽象——同一个字符串既能取出分词器，也能取出模型，前提是这个 checkpoint 的分词器词表和模型的 embedding 层是在同一次预训练里配对训练出来的。

为什么这对你重要：这个解耦是整个生态"随便换模型"的地基。没有它，每次换预训练权重都要手写一套新的文本预处理代码；有了它，换模型只是改一个字符串。但解耦也是脆弱点——如果你把 A 模型的权重配上 B 模型的分词器，代码不会报错，模型会安静地输出垃圾，因为 token ID 到词的映射已经对不上了。

适用边界这个抽象假设 tokenizer 和 model 永远配对使用。混用不同 checkpoint 的分词器和权重是新手最常见、也最隐蔽的错误——它不报错，只是效果差，排查成本很高。
Concept II

Trainer 三段式

是什么：Trainer API 把一次微调切成三段可配置流程——数据集加载与格式化 → 分词映射（tokenize + truncate + pad） → 训练循环（前向、反向、优化器步进、日志、评估、保存 checkpoint）。

原文定义：书中反复出现的模式是 dataset.map(tokenize_function, batched=True) 做第二段，Trainer(model, args, train_dataset, eval_dataset, compute_metrics) 做第三段——把原本要手写的几百行 PyTorch 训练循环压缩成几个参数配置。

为什么这对你重要：三段式不是语法糖，是一种可迁移的思维模型。无论后来你用不用 Trainer（比如换成更底层的 accelerate 或自己写循环），"先把数据变成统一形状，再让循环吃掉它"这个分解方式都成立。

适用边界Trainer 封装得越彻底，出问题时排查越难——学习率没收敛、显存溢出这类问题，答案往往藏在被封装掉的那部分代码里。这正是本书第 3 章要把 Transformer 内部解剖一遍的原因：高层 API 帮你跑通，不帮你看懂。
Concept III

任务头替换

是什么：同一个预训练 Transformer 主干（backbone），在顶端换一层不同的输出头，就能从做分类切换到做问答、命名实体识别或摘要。

原文定义：AutoModelForSequenceClassification、AutoModelForTokenClassification、AutoModelForQuestionAnswering、AutoModelForSeq2SeqLM——库里这一组以 AutoModelFor* 命名的类，字面上就是"同一个 Auto 家族，不同的 For"。

为什么这对你重要：理解"共用的是什么、不共用的是什么"，你才能判断迁移学习的边界在哪——backbone 学到的是通用语言表征，任务头学到的是"怎么把这份表征翻译成你要的输出格式"，前者可迁移，后者必须针对任务重新训练。

适用边界任务头能换，不代表所有任务都同样容易迁移。分类和 NER 的输出结构简单，任务头一般训练几个 epoch 就收敛；生成式任务（摘要、问答里的抽取/生成边界判断）的输出空间大得多，同样的数据量下效果差距明显——这也是概念 IV 里少标注学习要按任务类型分别讨论的原因。
Concept IV

少标注学习

是什么：当标注数据只有几十到几百条时，全参微调大概率过拟合，书里给出三条替代路径——零样本分类（用预训练模型的语言理解能力直接推断，不训练）、少样本学习（凭少量示例做上下文学习或轻量微调）、UDA 无监督数据增强（用未标注数据 + 数据增强扩充训练信号）。

原文定义：书中第 7 章把这三条路径按"能拿到多少标注数据"排成一个连续谱，而不是三选一的并列选项——数据量每往上走一格，就多一种可用的技术。

为什么这对你重要：这是全书最直接对抗"遇到任务就想着微调"这种本能的一章。数据不够时先微调，几乎总是错误的第一步——过拟合的模型在训练集上看着很好，一到真实分布就崩。

适用边界零样本和少样本对分类类任务效果较好，对生成式任务（摘要、开放式问答）通常不够稳定，因为生成任务的输出空间大、评估本身噪声就高。本书的这一章写于 LoRA/PEFT 生态成熟之前，今天工程界处理"数据不够但仍想微调"的默认选项已经是 LoRA/QLoRA，而不是书中的 UDA——详见效率与生态精读页的时代局限说明。
Concept V

知识蒸馏

是什么：用一个已经训练好的大模型（教师）指导一个小模型（学生）训练，学生不只学"正确答案"，还学教师模型对每个类别给出的完整概率分布（软标签）。

原文定义：这套方法的现代范式出自 Hinton、Vinyals、Dean 2015 年论文《Distilling the Knowledge in a Neural Network》，核心机制是温度缩放——用一个高于 1 的温度参数软化教师模型的输出分布，让学生模型能学到"教师觉得第二像、第三像的答案是什么"，而不只是"教师最终选了哪个"。DistilBERT 就是这套方法在 Transformer 上的经典应用（体积缩小 40%，速度提升 60%，保留 BERT 约 97% 的语言理解能力，这组数字出自 Hugging Face 官方论文，并非本站臆测）。

为什么这对你重要：蒸馏解决的是"模型已经训练好、但太大跑不动"的问题——它不是解决"数据不够"的工具，这是新手最常混淆的一点。

适用边界蒸馏效果的天花板由教师模型决定——教师本身有偏见或错误，学生会原样学会，蒸馏不具备纠错能力。且蒸馏本身也要一轮完整训练，不是免费的。
Concept VI

量化与剪枝

是什么：两条独立的推理效率优化路径。量化把模型权重从 32 位浮点压缩到 16 位、8 位甚至更低精度的整数表示，直接减小体积、加快计算；剪枝找出对输出影响很小的权重或注意力头，直接砍掉。

原文定义：书中第 5 章把这两条路径和知识蒸馏并列为"让 Transformer 在生产环境里能用"的三件工具，并给出用 ONNX Runtime 做推理加速的实操流程。

为什么这对你重要：三条路径（蒸馏、量化、剪枝）可以叠加使用，但顺序有讲究——一般先蒸馏出一个更小的模型，再对这个小模型做量化，而不是反过来，因为量化后的模型继续训练（蒸馏需要训练）会引入额外的数值误差。

适用边界量化和剪枝都有精度损失的临界点，压缩比例越高，输出质量下降越明显，且下降曲线不是线性的——往往在某个压缩比之后断崖式变差，需要实测校准，不能只按理论比例外推。
