BOOK 29 · NLP WITH TRANSFORMERS · 一套 Trainer，四种任务头

会调库的人很多，
知道什么时候
不该微调的人很少

Hugging Face 三位核心工程师写的这本书，表面是一本 transformers 库操作手册：分类、命名实体识别、问答、摘要，同一套 Trainer API 换个任务头就能跑通。但它真正的价值不在"怎么调库"，而在书里反复出现的那个判断——标注数据只有几十条时别微调，先试 few-shot；模型要部署到手机上别用全参微调，先想蒸馏或量化。这本书教的是工程判断力，代码只是它的载体。

一套 API，四个出口 · 全书真正的骨架不是"如何调 Trainer"，而是"什么时候该换哪个出口"——数据够不够、算力够不够、延迟要求苛不苛刻，三个变量决定路径。
Why This Book · 为什么读这一站

这本书早于 LoRA，但它教的判断力没有过期

2022 年成书时，参数高效微调（PEFT/LoRA）还没有成为行业默认选项，书里的"少标注数据"应对方案是零样本 / 少样本分类、UDA（无监督数据增强）和知识蒸馏，而不是今天更常见的 LoRA/QLoRA。这是一处**真实的时代局限**，本站会在效率与生态精读页明确标注，读者动手实践时应对照当代 peft 库。

但书的核心结构没有过期：Hugging Face 三位作者（Lewis Tunstall、Leandro von Werra、Thomas Wolf）把"用 Transformer 做 NLP"这件事拆成了一套可复制的流程——加载数据 → 分词映射 → 选任务头 → Trainer 训练 → 评估 → 效率优化。这套流程今天依然是业界的默认动作，只是"效率优化"那一格里的具体工具换了。读这本书，你学的是流程的骨架，不是某一版 API 的语法糖。

这一站要做的三件事 一、把"同一套 Trainer 打天下"这件事拆开看——分类、NER、问答、摘要四个任务头到底在哪里相同、在哪里不同。
二、把"标注数据不够怎么办"讲透——少样本、UDA、蒸馏三条路各自的适用边界。
三、老实标注这本书的时代局限：LoRA/PEFT 生态成熟之后，书里"效率优化"那一章的具体操作需要更新，但判断框架不需要。
Six Doors · 六张概念门

这一站的六个入口

Concept I

Tokenizer ↔ AutoModel 解耦

分词器和模型权重是两个独立的可替换组件，靠一个共享的 checkpoint 名字对齐。这个解耦是整套生态能"随便换模型"的地基。

 Concept II

Trainer 三段式

数据集 → 分词映射 → 训练循环。三段式把"写一个训练循环"这件事从几百行代码压缩成几个配置参数。

 Concept III

任务头替换

同一个 backbone，换一层输出头就能从分类切到问答。四个任务共用的是表征能力，不共用的是"怎么把表征读出来"。

 Concept IV

少标注学习

标注数据只有几十条时，微调不是唯一答案——零样本、少样本、UDA 数据增强，各自有各自的失效边界。

 Concept V

知识蒸馏

大模型的输出分布（软标签）比它的参数更值钱——蒸馏教小模型学"大模型犹豫的地方"，而不只是学"大模型答对的地方"。

 Concept VI

量化与剪枝

推理效率优化的两条独立路径：量化压缩数值精度，剪枝砍掉冗余连接。两条路径可以叠加，但各自有精度损失的临界点。
