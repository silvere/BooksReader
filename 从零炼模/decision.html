Application · 应用专题

读完这本书之后，你的项目该走哪条路

这本书教你理解"微调"这个动作本身；但一个真实项目该不该微调、该用哪种微调，答案不在这本书里，取决于你的任务、数据和预算。

Decision Table · 决策表

五条路径，成本和适用场景差一个数量级

路径成本量级什么时候该选它典型陷阱
只用 Prompt几乎为零任务能用自然语言说清楚，模型已有的知识和能力覆盖任务需求把本该用微调解决的"稳定输出格式"问题，硬塞进越来越长的 prompt
RAG（检索增强）低—中任务需要模型不知道的具体知识（内部文档、实时信息），但不需要改变模型的说话方式把"模型不知道"和"模型不会做"混为一谈——RAG 解决前者，解决不了后者
LoRA / 参数高效微调中需要改变模型的行为模式或专项能力，任务分布和预训练语料不算天差地别秩 r 选太小导致欠拟合，或误以为 LoRA 能像全参微调一样注入大量新知识
全参微调高任务分布和预训练差异很大，或需要极致的任务专项性能，且预算和数据规模都足够数据量不够时全参微调比 LoRA 更容易过拟合和灾难性遗忘
从零预训练极高（通常不该选）几乎只在你要研究模型本身、或所在领域的语料和现有模型的语言体系完全不兼容时才成立把"我想学会原理"和"我的产品该怎么做"混为一谈——这本书的六大概念解决前者，不建议直接套用到后者
一句话版本 能用 prompt 解决的不要 RAG，能用 RAG 解决的不要微调，能用 LoRA 解决的不要全参微调，能用现成开源模型微调解决的，基本不需要从零预训练。这本书的价值不在于让你走最贵的那条路，而在于让你在选更便宜的路径时，知道自己放弃了什么。
From Book to Project · 从教学规模到生产规模

书里的 1.24 亿参数，和你要微调的那个开源模型之间差什么

书中从零训练的模型是 GPT-2 small 规模（约 1.24 亿参数），单机甚至 CPU 都能跑通全流程。今天一个从业者更可能面对的场景，是在 Llama、Qwen 这类开源模型（70 亿到千亿参数级别）上做 LoRA 微调。这中间被这本书省略、但生产环境绕不开的几层：

  • 分布式训练与显存管理：单卡装不下的模型需要模型并行或量化（如 QLoRA），书中没有覆盖
  • 数据工程：真实指令数据集的清洗、去重、多样性控制，工作量往往超过训练本身
  • 评估体系：书中用"更强模型打分"作为教学示例，生产环境通常需要一套更系统的评测集和人工抽检流程
  • 推理部署：训练完成后如何量化、合并 LoRA 权重、部署成低延迟服务，是另一整套工程问题

这本书打的底子，让你在面对这些工程问题时，至少知道自己在"预训练模型"的哪一层做操作——这是判断力的起点，不是终点。

FINIS · 收束

压缩，是这本书没有明说的主题

预训练在做的事，换一个角度看是压缩：用几亿到几千亿个参数，压缩互联网规模语料里的统计规律。LoRA 的低秩假设也是一种压缩直觉——它赌的是"完成一个具体任务所需的权重改动，本身可以用远少于原矩阵的信息量描述"。这个"用最短的描述抓住规律"的想法，不是 LLM 领域的专利。

书架里的另一站：算法信息论 算法信息论站讨论的最小描述长度（MDL）和柯尔莫哥洛夫复杂度，问的是同一类问题的更一般版本：一段数据的"真正规律"，能被压缩到多短？预训练把语料压缩进模型参数，LoRA 把任务所需的改动压缩进两个低秩矩阵——两站从不同方向，逼近同一个直觉：理解，某种意义上就是压缩。
